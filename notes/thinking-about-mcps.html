The interesting thing about MCPs

A conversational interface is useful. The underlying product still has to solve a problem.

Denis Martins · Software & AI · 24 October 2026 · 1 min read

I've been interested in MCPs because of how naturally they let an assistant work with information in software I already use. Asking a CRM a question, or working with email in plain language, is a meaningful improvement over hunting through screens.

But where does the real value come from?

An MCP isn't the product

Putting a conversational interface in front of an empty or unhelpful application doesn't suddenly make it useful. The software still needs a purpose, reliable data, permissions and workflows that solve something real.

Start with the problem

I'd rather begin by identifying software people already need, then ask which tasks become easier when an assistant can retrieve information or take a controlled action. Authentication, access scopes and auditability should be part of that design, not an afterthought.

An MCP can make good software easier to use. It doesn't rescue a product nobody needed in the first place.
